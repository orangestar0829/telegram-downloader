# Telegram 私密频道图片 / 视频下载器

## 多账号下载（PR #4 预览）

主窗口点击 **多账号**，为每个 Telegram 账号分别设置 Session、SOCKS5 代理、
下载限速/并发、重试和定时扫描频道（数字优先级与每轮批次上限独立）。
原有账号 A 的设置、Session、扫描游标及下载历史均保留；在主窗口管理账号 A，
在多账号窗口切换管理其他账号。后台运行相互独立。
已加入的群组/频道列表支持名称关键词即时筛选（不区分大小写、支持中文及用户名），主窗口与 B 账号的群组列表均可使用。此功能只筛选已加载列表，不搜索群消息或产生额外的 Telegram 网络请求。
B 账号如果无法收到登录验证码，可以使用 **扫码登录**：在已经登录 B 账号的 Telegram 手机 App 中打开「设置 → 设备 → 连接桌面设备」扫描程序显示的二维码。二维码到期会自动刷新，支持两步验证；不会读取 AyuGram 的 Session。

同频道被多个账号启用监控时，各自扫描，任务入库后通过 SQLite 原子领取
**不同文件**，成功下载全局去重；关闭频道监控的账号不能领取该频道任务。
不提供“只下载不扫描”模式，没有频道权限的账号不会因此获得权限。

运行日志按天写入 `data/logs/runtime-YYYY-MM-DD.log`，默认保留 7 天；
GUI 的运行日志/下载记录支持账号筛选，避免一直累积日志导致内存上涨。
新增账号的 Session 和配置位于 `data/accounts/<id>/`。
**注意：旧版手动批量下载尚未接入跨账号租约，不要与其他账号的定时监控
同时操作相同频道。** 这是预览版的已知限制。

升级前备份 `data/`，数据库结构会自动无损扩展。
详见 [多账号 SQLite 迁移和回滚](docs/sqlite-multi-account-migration.md)。
PR 构建使用独立的 `preview-pr-4` **预发布测试包**，不发布正式 Release。

用 Telegram **官方 MTProto API**（Telethon）登录你自己的账号，下载**你已经加入**的频道或群里的图片和视频。

它不能破解没权限的频道，也不能绕过 Telegram 的成员限制。

## 能做什么

- 登录账号（手机号 + 验证码，如有二次验证会再要密码）
- 列出账号里的频道 / 超级群 / 群，并标出是否私密
- 按频道 ID、`@用户名`、`t.me` 链接或私密邀请链接下载
- 只下图片、只下视频，或两种都下
- 按日期范围、数量上限过滤
- 已下载过的文件自动跳过（可断点续下）
- 进度条显示每个文件

## 图形界面 (GUI，即点即用)

用起来就像 Telegram 官方客户端:**登录手机号 → 输验证码 → 自动列出你的群组/频道 → 选一个** → 在 **“浏览媒体”** 页像刷聊天一样看缩略图,**勾选想要的图片/视频,点“保存所选”**;也可以在“批量下载”页一次性全下。下载目录自动默认到 `下载/TelegramDownloader`,无需填写。

### 多频道监控：优先级、每轮数量与后台队列

- 每个频道可独立设置扫描间隔、**整数优先级（默认 0，数字越大越靠前）**、**每轮媒体数量（默认 100，可设为 20、500 等）**、扫描方向及**下载类型（图片/视频/GIF）**。在“多频道监控”页选中频道会回显其独立下载类型，点击“更新所选”保存；监控列表也显示类型，与“批量下载”页勾选框互不影响。旧版 `monitored_channels.json` 自动补齐默认值。
- 监控按优先级排序，但每次只扫描**最多 20 条消息**就让其他到期频道轮转；每轮媒体数量是该频道本轮累计匹配媒体的上限，不是连续阻塞其他频道的单次下载量。
- 运行日志默认使用**简洁模式**：每轮扫描开始记录一次，扫描期间的 20 条消息分片只累积统计、不反复刷屏；本轮结束时以一行 `[扫描]` 汇总检查、匹配、新增和跳过数量，达到上限则提示下轮续扫。优先级抢占后，只有任务真正进入暂停状态才统计为“已暂停”；同一时间段内同频道的暂停与恢复任务数各合并成一行 `[调度]`。异常信息仍按原有网络诊断和错误日志记录。扫描仅负责入队，不代表下载完成；实际文件下载完成仍单独写入“下载记录”标签页。
- 扫描只登记待下载媒体，实际传输由独立后台工作器处理：即使某个视频很大，扫描调度也不需要等待它下载完成。**监控下载沿用页面的媒体并发数**（文件槽位）；多个频道都有候选任务时，先给尚无活跃下载的频道机会，只有没有其他等待频道时才借用空闲槽位。相同槽位占用量时再综合各频道已占用的传输时间和数字优先级做公平分配，不按连续文件数量轮转。
- 不会强行取消已经开始的文件；如果某频道暂时是唯一有待下载任务的频道，它可以占满空闲槽位。高优先级频道有新任务时，可协作暂停低优先级传输并在完成后续传；相同优先级仍按空闲槽位和公平规则调度。文件内部分块并发独立于文件槽位。
- 当前下载进度中的“正在下载”与“已暂停”单独统计：并发上限只约束实际运行的文件，抢占后保留进度的暂停任务也会显示在列表中，但不占下载槽位。恢复时先显示“恢复中”，下一次数据块到达后转为“下载中”。**严格下载优先级**：更高优先级的待下载队列及正在下载文件未耗尽时，不恢复低优先级暂停文件；更高优先级处理完后，暂停文件先于同级新文件恢复（不设定时抢占/防饥饿例外）。暂停不等于取消或重新下载，实际交接仍需等当前网络请求到达安全边界。
- “批量下载”页的**文件并发、重试次数、分块并发和监控总限速**均为先编辑、再点击“应用并保存下载设置”统一验证和保存；输入过程中的临时数字不会改变运行中的下载速度。点击后，监控下载的文件并发、分块并发、总限速会动态生效，重试次数应用于后续启动的文件；调小文件并发不取消已开始任务，调大可继续派发。手动下载任务仍沿用其启动时的设置。
- **监控优先抢占、动态分块与总限速**：高优先级频道出现待下载媒体时，如果低优先级文件占满监控下载槽位，调度器会在已完成的数据块边界协作暂停低优先级文件（保留当前运行中的临时文件和下载进度），待优先级更高的文件下载后恢复；不会靠取消并重下整个大视频实现抢占。监控大文档（≥16 MiB）使用可调整的窗口下载方式，“单文件分块并发 (1-8)”可在运行中调整后续传输窗口，正在请求的窗口完成后响应调小。页面新增“监控总限速 (KiB/s，0=不限)”；这是**所有监控下载合计的平均接收速率**，当前运行中调整会迅速生效，但可能有单个 MTProto 块短时突发，且不能解除 Telegram 普通账户服务端限流。临时文件在程序退出后仍按原缓存清理策略处理，**跨程序重启续传尚不支持**。手动下载保持原模式，不使用该监控限速或暂停机制。
- 主窗口关闭时自动记录常规窗口的大小和位置到程序数据目录中的 `window_state.json`；下次启动优先恢复。若屏幕分辨率改变导致原位置不可见，则恢复默认大小，避免窗口跑出屏幕。最大化或最小化状态不会错误覆盖最后的常规窗口大小。
- 待下载媒体写入现有 SQLite 下载历史数据库中的 `pending_media` 表，和扫描游标一并提交；程序重新启动会接着处理未完成项目，已成功下载的消息继续去重，失败文件保留重试记录。
- **原有多文件并发和单文件分块并发设置保持不变**。本次只是改造多频道监控的扫描与后台执行，不涉及另行规划的统一任务队列和频道历史全量下载功能。

- **便携版(推荐，最不易被拦)**：从 [Releases](../../releases) 下载 `TelegramDownloader-*-portable-win64.zip`，解压后运行里面的 `TelegramDownloader.exe`。
- **安装版**：下载 `TelegramDownloader-Setup-*.exe` 安装,从桌面 / 开始菜单打开。
- **源码运行(零杀软误报)**：双击 `start-gui.cmd`，或命令行 `python -m tgdl gui`。

### 申请 api_id / api_hash 时 my.telegram.org 报错怎么办?

`my.telegram.org` 创建应用时经常弹一个笼统的 `ERROR`,这是它自己的老毛病,常见解决:

- **换浏览器 / 无痕窗口**,或**关掉 VPN/代理**后重试(有时反而需要挂梯子换个地区,两者都试试)。
- **App title / Short name** 用纯英文、别用特殊字符;URL 之类可留空或随便填 `https://example.com`。
- 点一次“Create application”若报错,**刷新页面看看其实已经创建**(常常已经生成了 api_id/api_hash)。
- 登录 `my.telegram.org` 本身要输 Telegram App 收到的验证码;若一直收不到,过几分钟再试。
- 实在申请不了:可以让**打包版内置**一对凭据(见下一节的 secret 方案),终端用户就不用自己申请。

### 为什么第一次要填 api_id / api_hash?

这是 Telegram **官方 API 的硬性要求**——任何 MTProto 客户端(包括官方 App)都需要,只是官方把它内置了。你只需在 https://my.telegram.org 申请一次,填进去程序就会**记住**,之后就只用登录手机号。

**想让打包出来的程序连 api_id/api_hash 都不用填**(真正“即点即用”):在 GitHub 仓库
`Settings → Secrets and variables → Actions` 里加两个 secret `TGDL_DEFAULT_API_ID`、
`TGDL_DEFAULT_API_HASH`(用你自己申请的),再打 tag 发版即可;发布出来的 exe 会内置这对
凭据,终端用户只需登录手机号。

### 浏览器/杀毒提示“检测到病毒”怎么办

这是 **PyInstaller 打包的未签名程序常见的误报**（不是真的病毒，是本项目自己打的包）。处理办法（任选）：

1. **优先用便携版 ZIP**：浏览器一般不拦 `.zip`。下载解压后运行 `TelegramDownloader.exe` 即可。
2. **让浏览器保留文件**：Chrome/Edge 下载栏里对被拦的文件点“保留 / 仍然保留”。
3. **Windows Defender 拦截**：在“病毒和威胁防护 → 允许的威胁 / 添加排除项”里允许该文件，或把安装目录加入排除。
4. **彻底不碰 exe**：装好 Python 后用上面的 `start-gui.cmd` 从源码运行，完全没有误报。
5. **根治(可选)**：给 exe 做**代码签名**（需购买 OV/EV 代码签名证书）后基本不再误报——这需要你的证书，我无法代办。

## 第一次使用

### 1. 申请 API（只需一次）

1. 打开 [https://my.telegram.org](https://my.telegram.org)
2. 用你的 Telegram 账号登录
3. 进入 **API development tools**
4. 创建一个应用，记下 `api_id` 和 `api_hash`

这两项是 Telegram 发给**你的账号**的开发凭证，不要发给别人。

### 2. 填写配置

双击 `run.cmd`。第一次会复制 `.env.example` 为 `.env` 并打开记事本。填：

```
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=你的hash
TELEGRAM_PHONE=+8613800138000
DOWNLOAD_DIR=./downloads
```

手机号建议带国际区号。`TELEGRAM_PHONE` 也可以留空，运行时再输入。

### 3. 登录

```text
run.cmd login
```

Telegram 会把验证码发到 App。输入后会在本目录生成 `tgdl_session.session`。这个文件 = 登录态，**不要上传、不要发给任何人**。

### 4. 列出频道

```text
run.cmd list
```

私密频道没有 `@username`，请复制左侧数字 ID，例如 `-1001234567890`。

### 5. 下载

```text
run.cmd download --channel -1001234567890
run.cmd download --channel @somechannel --type photo
run.cmd download --channel "https://t.me/+xxxxxxxx" --type video --limit 50
run.cmd download --channel -1001234567890 --since 2026-01-01 --until 2026-08-01
```

不带参数双击 `run.cmd` 会进入菜单。

文件保存在：

```text
downloads/频道名/photos/
downloads/频道名/videos/
```

文件名：`日期_消息ID.扩展名`

## 命令一览

| 命令 | 作用 |
|------|------|
| `python -m tgdl` | 交互菜单 |
| `python -m tgdl gui` | 图形界面 |
| `python -m tgdl login` | 登录 |
| `python -m tgdl list` | 列出频道 |
| `python -m tgdl download -c ID` | 下载 Telegram 里的图/视频 |
| `python -m tgdl parse -c ID` | 链接解析机器人：保留链接、预览，并尝试直链下载 |

`download` 常用参数：

- `-c / --channel` 频道 ID、用户名或链接
- `-t / --type` `photo`、`video`、`animation`、`all`（默认 `photo,video`）
- `-n / --limit` 最多保存多少个文件
- `--since` / `--until` 日期 `YYYY-MM-DD`
- `--no-skip` 即使已存在也重新下载
- `--dry-run` 只列出匹配的图片/视频，不下载

## 内置链接解析机器人（parse）

资源群里常见「文字 + 链接 + Telegram 预览图」。`parse` 会：

1. **保留所有链接**（写入 `parsed/links.jsonl` 和 `parsed/links.md`）
2. **保存 Telegram 链接预览**
3. **HTTP 直链**图片/视频 → `parsed/direct/`
4. **磁力链接 / `.torrent` 文件** → `parsed/torrents/`（需 aria2 或 libtorrent）
5. **`t.me` 帖子**：账号能打开则收下媒体
6. **网盘链接**：只写入清单（百度/夸克/阿里云盘等走官方客户端）

BT 引擎优先用本机 `aria2c`，没有则尝试 `pip install libtorrent`。

Windows 安装 aria2：从 https://github.com/aria2/aria2/releases 下载，把 `aria2c.exe` 放到 PATH，或放到 `C:\aria2\aria2c.exe`。

```text
run.cmd parse --channel -1001234567890
run.cmd parse --channel -1001234567890 --dry-run --limit 80
run.cmd parse --channel -1001234567890 --catalog-only
run.cmd parse --channel -1001234567890 --no-bt
```

`--catalog-only`：只存清单，不下直链/BT。  
`--no-bt`：解析磁力/种子但不启动下载。  
`--no-previews`：不保存 Telegram 预览图。

输出目录：

```text
downloads/频道名/photos/
downloads/频道名/videos/
downloads/频道名/parsed/direct/
downloads/频道名/parsed/torrents/
downloads/频道名/parsed/links.md
```

资源群 / 链接预览也会扫到：

- 机器人发出的照片、视频、相册：**会下载**
- 机器人把视频/图片当文件发出（`.mp4` / `.jpg` 等）：**会下载**
- 消息里的链接预览大图 / 预览视频：**会下载**
- 磁力 / `.torrent`：安装 aria2 后 **会下载**
- 网盘分享页：只保存链接

只看会下哪些、先不下：

```text
run.cmd download --channel -1001234567890 --dry-run --limit 30
```

```text
copy .env.example .env
.venv\Scripts\python -m tgdl list
```

## 使用限制（请务必遵守）

- 只能下载**当前登录账号已经加入**的对话。
- 请尊重版权和频道规定，下载内容仅供个人备份。
- 不要把 `.env`、`*.session` 提交到 Git 或发给别人。
- 下载太快可能触发 Telegram 限流（Flood wait）。脚本会提示需要等待的秒数，稍后再跑即可；已下过的文件会跳过。
- 这不是破解工具。打不开的私密频道，说明你的账号没有权限。

## 常见问题

**提示 Missing TELEGRAM_API_ID**  
还没填 `.env`，或文件不在项目根目录。

**Cannot access / ChannelPrivateError**  
账号还没加入该频道。先在 Telegram 里加入，再 `list` 复制 ID。

**一直要验证码**  
删掉目录里的 `tgdl_session.session` 后重新 `login`。不要多开好几个脚本同时登录。

**只下到一部分就停了**  
遇到限流。看终端里的秒数，等结束再执行同一条命令（会跳过已有文件）。

## 本 Fork 的 SOCKS5 / 媒体性能改进

- **代理**：GUI → 设置 → SOCKS5 主机、端口（例如 Karing 本地监听的 `127.0.0.1:1080`）。保存后重启下载器，所有 Telegram MTProto 登录和媒体请求会通过该 SOCKS5 代理。不设置则维持原来的直接连接或系统 TUN 路由。这里应填写 Karing **实际 SOCKS5 监听端口**，而不是代理节点的远端端口。
- **加解密**：安装 `cryptg`，由 Telethon 自动优先使用；提升幅度依设备及网络条件而异。
- **批量下载与画廊保存**：并发 1–8（默认 3），每个失败文件最多重试 0–5 次（默认 2），每个文件使用独立临时目录防止文件名冲突。遇到 Telegram FloodWait 时停止并发任务，不强制重试。
- **CLI**：`python -m tgdl download -c GROUP_ID --concurrency 3 --retries 2`。
- **重要**：这里实现的是多个文件之间的并发，不对单个视频做分块并行；如家宽到代理节点的线路本身受限，并发与 `cryptg` 不一定提速。

### 单文件分块并发下载

**PR 预览构建**：向 `main` 提交 Pull Request 时，`.github/workflows/pr-windows-build.yml`
会在 Windows runner 上测试并生成安装版 EXE 与便携版 ZIP，作为 Actions Artifacts 保存 30 天，
不修改 `main`，也不发布正式 Release。PR 包默认不包含 Telegram API 凭据；
可沿用旧版的 `.env` 和有效 Session。

**分块稳定性**：每个分块等待数据超过 45 秒会重试（最多两次），
分块持续失败则自动退回 Telethon 普通下载。日志中显示分块累计已接收量与百分比，
主界面新增「查看日志」独立窗口。预分配的 `data.mp4` 不代表下载完成；
只有所有区间验证成功才会移入最终目录。

**定时下载**：GUI「批量下载」页选择频道、媒体类型，填写「自动下载间隔(分钟)」
（默认 30，范围 1-1440），点击「启动定时」立即下载首轮，此后按固定间隔检查。
已经存在的媒体文件会跳过；若上一轮仍在运行则跳过当前轮，不会叠加并发。
点击「停止定时」停止后续检查，不中断正在下载的任务。
定时功能仅在程序运行期间有效，关闭程序后不会后台下载或自动恢复。

**SQLite 下载历史**：批量频道下载使用 Windows
`%LOCALAPPDATA%\TelegramDownloader\tgdl_download_history.sqlite3`
（Linux 为 `~/.local/share/TelegramDownloader/tgdl_download_history.sqlite3`）
记录成功保存过的媒体，以频道 ID + 消息 ID
去重。上传网盘后删除本地媒体，不会触发再次下载。第一次运行新版时，
仍在本地的历史文件会在扫描到对应消息时自动补录；**升级前已经删除的媒体无法
仅凭本地文件恢复下载记录**，首次扫描可能再次下载它们。请备份此数据库，
不要将它与清理媒体文件一起删除；数据库独立于程序安装目录，升级便携版无需迁移它。
下载失败不会被标记为成功。手动选择图库媒体的保存流程仍使用原有文件去重。

**便携版数据目录**：Windows 便携 ZIP 内的 `portable.flag` 标记便携模式。
启动后所有用户状态保存在 `TelegramDownloader.exe` 同级的 `data/`：
`data/.env`、`data/tgdl_session.session` 和
`data/tgdl_download_history.sqlite3`。从旧版升级时会尝试从旧目录和
`%LOCALAPPDATA%\TelegramDownloader` 复制现有数据（不会覆盖 `data/` 内已有文件）。
更新时替换程序文件，保留整个 `data/` 目录。安装版仍将数据存入用户目录，
避免写入 Program Files 失败。

**多频道监控**：GUI 的「多频道监控」页可将当前选中或手动输入的频道
加入监控列表，为每个频道设置独立的扫描间隔（1～1440 分钟）及媒体类型。
列表可暂停、启用、删除频道。设置保存在 `data/monitored_channels.json`
（安装版为用户数据目录），重启后保留；启动监控需要手动点击。
所有频道共用一个 Telegram 客户端、下载队列和 SQLite 下载历史，
同一时间只运行一个频道扫描；繁忙时到期的频道顺延执行。
旧版单频道定时下载仍可使用，但两种定时模式不可同时运行。

**日志分流**：GUI 的「运行日志」保留扫描、重试、连接错误和回退等信息；
「下载记录」单独显示每个成功保存文件的大小、耗时、平均速度和下载方式。
分块正常下载不再逐秒报告百分比。查看历史日志时不会被新日志强制拉到底部，
可以点击「跳转最新」继续自动跟随。

**增量扫描与安全退出**：多频道监控为每个频道保存扫描方向
（「从新到旧」或「从旧到新」，旧配置默认从新到旧）。
首次全量遍历频道当前可见的历史消息，后续只处理高于持久化检查点的新消息，
包括程序离线期间仍存在的消息；已删除的 Telegram 消息无法恢复。
每批最多匹配 100 个媒体，处理完后让其他到期频道有机会执行。
扫描状态和失败待重试消息保存在现有 SQLite 中新增的表，不修改或删除
`downloaded_media` 下载历史；媒体类型改变时会重新遍历历史以免跳过新类型。
「停止监控」只阻止后续扫描；「取消当前下载」立即取消当前批次。
监控规则列表同时展示频道名称与 ID，旧规则在登录刷新列表或实际扫描时自动补齐名称，
不需要删除重建；下载完成日志也带来源频道名称。
每批扫描日志显示方向、消息 ID 区间、扫描游标和区间上限，
并展示本次程序运行期间该频道当前扫描轮次的累计匹配/下载/跳过/失败数量。

**分块磁盘 I/O**：多路下载仍然直接写入单个预扩展文件的不同偏移区间，
无需额外合并文件；每路使用 1 MiB 文件缓冲区。完成记录附带「文件准备 /
分块传输 / 最终保存」各阶段耗时，便于判断 Windows 磁盘预分配、
网络传输或最终重命名是否成为瓶颈。此优化不改变失败时的自动回退、
临时文件清理以及下载成功后的 SQLite 去重。
对于最终下载目录在机械盘（如 E:）的情况，可在 GUI「设置」填写
「分块临时目录」（例如 SSD 上的 `C:\\TelegramDownloaderTemp`），
或在 `.env` 配置 `TEMP_DOWNLOAD_DIR=C:\\TelegramDownloaderTemp`。
程序先在临时盘并行写入分块，再以单路顺序复制至最终磁盘上的隐藏临时文件，
复制成功后才重命名为正式文件并写入下载历史；其他文件的跨盘复制也会依次进行，
避免多个文件同时造成机械盘随机寻道。若暂存盘与下载盘位于同一卷，
仍使用直接重命名，不额外复制。SSD 缓存同时受两项限制：
所有正在暂存的文件预留空间合计最多 **20 GiB**，且要求 SSD
至少保留 **10 GiB** 可用空间。额度不足时异步排队等待，不回退到机械盘，
跨盘复制完成并清理临时文件后释放额度；其他程序释放空间后也会自动重试。
超过单文件 20 GiB 上限会明确报错，避免无限等待。此缓存上限是本进程
预留额度。GUI 现在会在启动时检查 SSD 缓存和下载目录中的临时文件，
自动删除**带有效本程序所有权标记且文件锁已释放**的残留目录（包括
跨盘复制中断留下的文件），不会删除有进程正在使用的文件。
设置页面提供「检查并清理残留缓存」：旧版没有所有权标记的临时目录
只能在确认其他旧版进程均已退出后手动清理，所有权标记损坏的目录保持不动。
GUI 额外提供单实例保护，第二次启动会提醒切换至已运行窗口；异常退出后
系统会自动释放单实例互斥锁，重启不受影响。所有清理均不涉及已完成文件、
SQLite 历史、监控配置和登录会话。

**实时下载进度**：日志区域上方增加「当前下载进度」面板，最多可同时
显示各文件独立的群组/文件名、下载字节数、百分比、速度和当前状态。
普通媒体下载通过 Telethon 进度回调采样，分块并行下载按实际收到的
字节数累加（不会误用预分配文件大小计算百分比），约每 250 毫秒
更新一次；等待 SSD 空间、创建文件、跨盘复制和自动重试也会显示状态。
完成、失败或取消的任务短暂保留后自动从实时列表移除，完整结果仍保存在
「下载记录」标签页，运行日志保持独立，避免频繁写入进度日志。
主界面采用上下可拖动分隔栏，默认给实时进度和日志约一半可用空间；
可拖动分隔线，在监控列表与日志之间分配高度。监控表初始高度缩小，
日志文字采用等宽字体便于查看时间戳和网络异常，放大窗口和
「放大查看」按钮仍可使用。

**网络诊断埋点**：分块下载连续 10 秒没有收到新的字节时，
运行日志会以「[分块诊断]」显示文件、分块编号、等待时间、累计字节和请求尝试次数；
若持续等待则最多每 20 秒重复一次，恢复接收数据时记录实际等待时长。
GUI 另外把 Telethon 原有 INFO 级的 FloodWait 自动休眠、MTProto 自动重连、
连接被关闭等事件安全提取为「[网络诊断]」日志，同种事件 5 秒内限频。
这些诊断只观察传输，不改变 Telegram 请求大小、下载并发、45 秒请求超时、
重试次数、限流等待策略或下载历史。日志不会包含代理密码或 Telegram 会话密钥。

Telethon 1.46.0 原生 FloodWait INFO 日志无法区分
`FLOOD_WAIT` 与 `FLOOD_PREMIUM_WAIT`；下载器现在还会无侵入地观察
`GetFileRequest` 服务端原始异常（包括媒体 DC 的共享连接），分别计数，
输出「服务端原始响应 FLOOD_WAIT / FLOOD_PREMIUM_WAIT」及要求等待的累计秒数。
自动等待日志仅表示 Telethon 的暂停动作，不据此猜测限流类型；累计秒数是
服务端要求等待的合计，**并非实际墙钟阻塞时间**，也不代表所有并发任务
应相加的耗时。完成日志同时展示文件全程均速与媒体传输阶段均速；
并发期间限流计数标记「同期全局」，不能归因到某一个文件。

浏览媒体页勾选文件后点击「保存所选」也会登记为当前下载任务；
多频道监控页的「取消当前下载」现在可取消这类手动任务，安全退出时同样
会等待正在进行的任务结束或取消清理。已保存成功的文件不会被删除。

RPC 请求错误不再统一记为笼统的「Telegram RPC 内部错误」。
对于 `GetFileRequest`，现在在服务器返回异常时记录具体类名
（例如 `TimedOutError`、`RpcCallFailError`、`RpcMcgetFailError`）、
该异常的累计发生次数及 Telethon 固有的约 2 秒重试等待说明。
下载完成记录将展示下载期间「同期全局」各类文件 RPC 异常的计数与
名义等待时间；该数字不是单文件精确归因，也不是实际墙钟阻塞时间。
不会改变 Telethon 自带的重试策略或下载并发控制。
此选项默认关闭，不会擅自使用系统盘；更改设置后需重新启动程序。
关闭窗口且有下载正在进行时，会询问是否等待已经开始的文件完成后退出、
取消当前下载后退出，或继续运行。等待模式不会启动新文件，但当前文件的
分块会继续写完并更新 SQLite。取消模式不提供分块级断点续传。

CHUNK_CONCURRENCY 默认 1，设置为 2/4/8 后对不小于 16 MiB 的 Telegram Document 启用 Telethon iter_download 的并行字节区间读取。每段有严格长度校验，只有全部区间下载成功才将临时文件移动为最终文件。纯字节拼接，不需 FFmpeg，不重新编码；较小文件及普通相册图片仍由标准下载流程处理。文件并发与分块并发独立，但会叠加网络请求；不保证速度提升。

命令行：python -m tgdl download -c GROUP_ID --concurrency 3 --chunk-concurrency 4 --retries 2
